1.4 Multi-PC Deployment & Portable Model Directory Setup

Goal: Run seamlessly across multiple computers (Home PC, Office Desktop, Laptop) without broken drive paths.

When transferring this repository to another PC or drive where paths differ:

  1. The MODELS_DIR Configuration Key: Set "MODELS_DIR" in config.json to the folder where your GGUF/bin models are saved on that computer: json "MODELS_DIR": "/home/username/models" Or use a project-relative path: json "MODELS_DIR": "./models"

  2. Zero-Configuration ./models/ Drop-In: If you copy your model files directly into <project_root>/models/, the system automatically discovers and loads them without requiring any configuration edits!

  3. Environment Variable Override ($MODELS_DIR): You can also set the location system-wide via environment variables in your terminal or ~/.bashrc: bash export MODELS_DIR="/path/to/my/models" # or export VOICE_MODELS_DIR="/path/to/my/models"

  4. Multi-Tier Fallback Discovery Hierarchy: If a configured model path cannot be found at its primary location, the ASR factory automatically searches the following locations in order:

  5. Explicit "MODELS_DIR" in config.json
  6. Environment variables: $MODELS_DIR, $VOICE_MODELS_DIR, $HANDY_MODELS_DIR
  7. Repository local folder: <project_root>/models/<filename>
  8. User standard data folder: ~/.local/share/voice_to_refinedtext/models/<filename>
  9. User cache folder: ~/.cache/voice_to_refinedtext/models/<filename>

  10. Primary development path: /media/manoj/F1/models-handy/<filename>

  11. Hugging Face Cache Portability (audio_to_idea): If cache_root in audio_to_idea_config.json points to an external drive that is unplugged or absent on the current PC, the system automatically and silently falls back to standard ~/.cache/huggingface/hub instead of halting.

5. PWD Language Helper & Hybrid CLI (pwd_cli.py & pwd_helper/)

The PWD Language Helper integrates civil engineering and departmental terminology from Uttarakhand Public Works Department directly into both the real-time speech engine and a standalone terminal/CLI utility.

5.1 Architecture & Components

  • Core Dictionary (pwd_dict.json): Contains 53 standard PWD designations, document types, and technical abbreviations categorized into officers, documents, schemes, and technical.
  • Custom Extension (custom_dict.json): Place in pwd_helper/custom_dict.json or your project root to append personal or local project abbreviations without modifying core files.
  • In-Flight Speech Normalizer (pwd_helper.normalizer): Auto-corrects spoken abbreviations during dictation (e.g. "the ee met the ae to review the mb for rcc culvert" $\rightarrow$ "the EE met the AE to review the MB for RCC culvert").
  • Tri-Tier Translator (pwd_helper.translator): 1. Ollama LLM: Context-aware domain translation via local models (qwen2.5:3b / llama3-hindi). 2. Online Fallback: Zero-dependency pure Python Google Translate fallback. 3. Offline Argos: Direct local neural translation (optional).

5.2 Terminal & CLI Commands (pwd_cli.py)

Run directly in your terminal:

# 1. Quick Abbreviation Lookup
./pwd_cli.py ee
# Output: [officers] EE = Executive Engineer (अधिशासी अभियंता)

# 2. Lookup and Copy to Clipboard
./pwd_cli.py nit -c

# 3. Bilingual Translation
./pwd_cli.py translate "Bridge inspection"
# Output: Hindi (online_google): पुल निरीक्षण

# 4. Search by English or Hindi keyword
./pwd_cli.py search "निविदा"
./pwd_cli.py search "tender"

# 5. Interactive REPL (with Voice Dictation toggle)
./pwd_cli.py
pwd> search engineer
pwd> ee
pwd> v               # Activates microphone dictation directly inside the CLI!

8. Tuning & Optimization Guide

Microphone Silence Calibration

If the assistant cuts you off too quickly or captures room noise: 1. Speak normally and observe if recording ends naturally ~2 seconds after you stop. 2. If recording ends while you are still speaking: decrease SILENCE_THRESHOLD (e.g. from 300 to 200). 3. If recording keeps running due to room fan or typing noise: increase SILENCE_THRESHOLD (e.g. from 300 to 450).

Wayland Direct Typing Setup

On Ubuntu Wayland sessions, xdotool cannot simulate keystrokes directly. The application automatically uses ydotool. To enable ydotool without requiring root permissions:

sudo systemctl enable --now ydotool
sudo usermod -aG ydotoold $USER

Log out and log back in once. Typing will now work seamlessly across any Wayland or X11 application!

9.2 Key Architectural Principles for Peak Accuracy

  1. Why Model-Specific Prompts Matter (prompts/<model_alias>/): - llama3-hindi: Fine-tuned on Hindi instruction datasets. When prompted with English instructions (even if asking for Hindi output), it tends to respond in English and over-translate. Its dedicated prompt folder (prompts/llama3_hindi/) uses native Hindi Devanagari system prompts to enforce strict obedience. - qwen2.5:3b: Exceptionally fast and obedient, but can over-interpret unfamiliar Devanagari transcriptions. Its prompt folder (prompts/qwen2.5_3b/) incorporates explicit Phonetic & Script Recovery Rules so that Devanagari-transcribed English phonetics ("मी" $\rightarrow$ MB, "हिड्स" $\rightarrow$ he needs) are correctly recovered without hallucinating false metaphors.

  2. Smart ASR Coupling at the Speech Layer: - In pure_english mode, the engine automatically forces language="en" and injects civil engineering vocabulary cues (EE, AE, JE, NIT, MB, RCC) into Whisper's initial prompt. This prevents Whisper from misdetecting Indian English accents as Hindi, eliminating Devanagari garbling before it ever reaches the LLM. - In pure_hindi mode, the engine forces language="hi" with _HINDI_PROMPT, bypassing Whisper's language-detection roundtrip for instant Devanagari transcription.

  3. ASR Engine Differences: - nemotron_fast (NVIDIA Nemotron 3.5 Streaming GGUF): Lightning-fast (~138ms on RTX 3060). English speech only. Best for pure English dictation, email drafting, and coding notes. - whisper_large_v3 (Faster-Whisper): Gold standard for mixed Hindi-English audio, heavy regional accents, and official Hindi dictation. - whisper_turbo: Excellent balance of speed (~0.4s) and bilingual accuracy for day-to-day mixed dictation.
